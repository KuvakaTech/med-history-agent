Step 5 — The finished record, and correcting it

GET /api/v1/cabin/{id}/record returns the full clinical content — the read every later Phase 2 step is built on. POST …/override applies a doctor correction with an audit entry.

Two behaviours worth deliberately provoking here: overriding a session that is still active returns 409 (the live flush loop would overwrite the correction within 15s, so it is refused rather than silently lost), and a protected field or a bad value returns 422 with the record left untouched.
